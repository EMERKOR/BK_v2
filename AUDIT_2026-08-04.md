# Ball Knower v2 — Data and Profile Audit, 2026-08-04

Reference document. Records what was verified, what was fixed and why, and
what is still broken. Not a task list.

Everything here was confirmed by running code and cross-checking output
against nflverse. `KNOWN_ISSUES.md`, `ARCHITECTURE.md`, and `WORKLOG.md`
predate this audit and were not treated as reliable.

---

## 1. Data verification

4,050 games from 2011 through 2025 week 14 were compared against
`nflverse/nfldata/data/games.csv`.

| Check | Result |
|---|---|
| Games matched to nflverse | 4,050 / 4,050 |
| Home score mismatches | 0 |
| Away score mismatches | 0 |
| Spread exact matches | 4,028 / 4,050 |
| Duplicate game IDs | 0 |
| Null values in market or score data | 0 |

All 22 spread mismatches fall in 2025 weeks 15–16. See section 5.

### Spread sign convention

This project uses **negative = home favored**. nflverse `spread_line` uses
**positive = home favored**. The two are exact inverses across all 15
seasons.

The ATS math in `record.py::_compute_team_records` assumes this project's
convention. Changing it to match nflverse without flipping the sign on load
will invert every ATS result in the repo.

## 2. The failure pattern

Three of the four bugs below share one shape.

The code built a file path or looked for a column name that does not match
what is on disk. Each lookup sat inside an `if path.exists()` or
`if "col" in df.columns` guard. When the guard failed, the code skipped the
work and returned defaults.

No exception. No warning. The builder printed row counts and checkmarks
while writing columns that contained nothing.

`ats_wins` was 0 on all 736 rows of `record_2024` and nothing reported it.

**Implication for future work:** when touching any loader in this codebase,
confirm the path it constructs against the actual directory listing.

## 3. Fixes applied

### `ball_knower/profiles/record.py`

Seven columns were 0 across all 736 rows: `ats_wins`, `ats_losses`,
`ats_pushes`, `ou_overs`, `ou_unders`, `division_wins`, `division_losses`.

Three stacked causes:

1. `_load_schedule_and_scores` read
   `data/RAW_market/{season}/market_week_{NN}.csv`.
   Actual layout is `data/RAW_market/spread/{season}/spread_week_{NN}.csv`
   and `data/RAW_market/total/{season}/total_week_{NN}.csv`.
2. It then looked for columns `spread_line` and `total_line`. Actual columns
   are `market_closing_spread` and `market_closing_total`.
3. `division_wins` and `division_losses` were hardcoded to 0 with a comment
   saying division info was unavailable. It was in
   `data/profiles/identity/teams.parquet` the whole time.

Fix: load both market folders, rename columns on read, add a cached
`_team_divisions()` lookup from the identity bucket.

Verified: 2024 ATS records recomputed independently from nflverse match on
32 of 32 teams. Division game counts are 6 for 28 teams and 7 for BAL, PHI,
PIT, WAS — those four played a division rival in the playoffs, which is
correct.

### `ball_knower/profiles/coverage.py`

Bucket returned 0 rows for 2024 and reported success.

The loader globbed
`data/RAW_fantasypoints/coverage_matrix_def_{season}_w*.csv`. Those files
exist only for 2025. Seasons 2022–2024 live at
`data/RAW_fantasypoints/coverage/defense/coverage_defense_{season}_w{NN}.csv`
with an identical schema.

Second issue in the same files: these FantasyPoints exports append a column
glossary to the bottom. A 2024 week 10 file contains 28 real team rows
followed by 19 rows named things like "Games Played", "Dropbacks", and
"Cover 3 Rate". A naive read treats those as NFL teams. They carry a null
`Season` value, which is how they are filtered.

Fix: check both naming schemes, glob both, drop rows with null `Season`.

Result: 570 rows for 2024. Unlocks man rate, zone rate, single-high vs
two-high shell rate, and Cover 0 through Cover 6 percentages per team per
week for 2022–2025.

### `ball_knower/profiles/coaching.py`

`play_action_rate` was 0.20 and `motion_rate` was 0.40 for all 32 teams
every week. Constant columns carry no signal.

Both were hardcoded defaults. The motion lookup checked for a column named
`motion` or `pre_snap_motion` in the play-by-play. nflfastR's play-by-play
has neither.

Fix: FTN charting carries `is_play_action`, `is_motion`, and `n_blitzers`
from 2022 onward, via `nflreadpy.load_ftn_charting()`. Joined to
play-by-play on `(nflverse_game_id, nflverse_play_id)` against
`(game_id, play_id)`. Cached to `data/RAW_ftn/`.

Verified: 2024 league play action rate is 0.106, so the old 0.20 constant
was roughly double reality. Computed range is 0.079 to 0.186. LAR leads
motion at 0.744 under McVay; DET leads play action at 0.186 under Ben
Johnson. Both are known traits.

### `validate_profiles.py` — new, repo root

Checks every column in every profile bucket for: all null, all zero,
constant, out of plausible range, and duplicate primary keys. Recomputes the
record bucket from nflverse and compares. Exits 1 on any failure.

Two guards in this file exist because of specific bugs. Do not remove them:

- **`ALIASES`** maps nflverse team codes to this project's codes. nflverse
  writes the Rams as `LA`; this project normalizes to `LAR`. Without the map
  that team drops from the comparison silently. This gap caused two separate
  checks to skip a team, and one published result to be wrong.
- **`ALLOWED_ZERO`** contains `ties`. The 2024 NFL season had zero ties, so
  an all-zero ties column is correct. Confirm the true value before adding
  anything else to that set.

## 5. Known broken, not yet addressed

**Roster bucket crashes.** It imports `nfl_data_py`, which nflverse retired
in favor of `nflreadpy`. This is the only bucket that fails outright, and
all player-level matchup work depends on it.

**2025 data is incomplete and partly wrong.**

- Scores and market data stop at week 16
- Play-by-play stops at week 14
- Weeks 17, 18, and the playoffs are missing entirely
- No `injuries_2025.parquet` exists
- 29 games in weeks 15–16 disagree with nflverse on spread or total. The
  worst is KC at TEN week 16: this repo has KC by 11.5, nflverse has KC by
  3.5. Re-pull both weeks rather than reconciling them.

Everything from 2011 through 2025 week 14 is verified clean.

## 6. Rebuilding the FTN cache

`coaching.py` reads from `data/RAW_ftn/`, which is generated rather than
downloaded with the rest of the raw data. 2.2 MB, four files. If it is
missing, `coaching.py` silently falls back to the old constants.

```bash
python -c "
import nflreadpy as nfl, pathlib
pathlib.Path('data/RAW_ftn').mkdir(parents=True, exist_ok=True)
for y in [2022, 2023, 2024, 2025]:
    nfl.load_ftn_charting([y]).to_pandas().to_parquet(f'data/RAW_ftn/ftn_{y}.parquet', index=False)
    print('cached', y)
"
```

`.gitignore` excludes generated directories under `data/` but keeps `RAW_*`,
so this folder is committed alongside the other raw data.
